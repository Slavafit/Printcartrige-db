# Task 018 — Mass Consumables Compatibility Expansion

## Цель

Массово расширить базу совместимости PrinterDB, уделив приоритетное внимание **HP, Epson и Canon**.

Главный критерий успеха — не количество добавленных моделей принтеров, а **увеличение количества принтеров, для которых можно найти подходящий расходный материал по модели устройства**.

Задание должно развивать результаты Task 016 и не конфликтовать с выполняемой Task 017 (OpenPrinting).

## 1. Анализ существующей базы

Перед реализацией новых импортёров:

- Изучить актуальную схему SQLite и импортёры.
- Проверить результаты Task 016 и Task 017, если последняя уже объединена.
- Определить количество принтеров с расходниками и без них.
- Сформировать отдельную статистику по HP, Epson и Canon.
- Определить количество уникальных расходников и связей.
- Выявить возможные дубли и варианты написания моделей.
- Сохранить исходные показатели для сравнения после импорта.

Не использовать количество записей как единственный показатель покрытия.

## 2. Поиск массовых источников

Найти доступные наборы данных с реальными связями между принтерами и расходными материалами.

Приоритет:

1. HP — LaserJet, Color LaserJet, DeskJet, OfficeJet.
2. Canon — PIXMA, i-SENSYS, MAXIFY.
3. Epson — WorkForce, Expression, EcoTank.

Рассматривать открытые репозитории, структурированные каталоги, CSV, TSV, JSON, XML и доступные справочники совместимости.

Для каждого источника задокументировать:

- URL и владельца данных;
- лицензию и ограничения использования;
- формат и пример структуры;
- примерное количество моделей и связей;
- наличие точных артикулов;
- качество идентификации принтеров;
- возможность воспроизводимого импорта.

Не использовать источники, запрещающие предполагаемый способ получения или повторного использования данных. Не обходить ограничения сайтов.

Если пригодные источники не найдены, представить отчёт с объяснением и не генерировать искусственные записи.

## 3. Импорт совместимости

Использовать существующий механизм Multi-source Import.

Каждая запись должна содержать, насколько позволяет источник:

- производителя принтера;
- точную модель принтера;
- артикул расходного материала;
- производителя расходного материала;
- тип расходника;
- цвет;
- регион;
- источник данных;
- дату получения информации;
- степень достоверности.

Поддерживать связи many-to-many.

Один расходник может подходить нескольким принтерам, а один принтер — использовать несколько расходников.

## 4. Классификация расходников

Различать:

- OEM;
- compatible;
- remanufactured;
- unknown.

Если происхождение не установлено, сохранять `unknown`.

Не присваивать статус официально подтверждённого расходника на основании стороннего каталога.

Особое внимание уделить Epson EcoTank: бутылочки с чернилами являются полезными расходниками, хотя не являются картриджами.

Проверить, позволяет ли текущая модель данных корректно хранить такие расходники. Если нет, подготовить безопасное расширение схемы с миграцией и обратной совместимостью.

Не переименовывать бутылочки в картриджи и не нарушать существующие ограничения строгого OEM-импорта. Если требуется изменение правил из Task 005, явно документировать его и реализовать отдельно от логики официальной верификации.

## 5. Нормализация и устранение дублей

Обеспечить корректную обработку:

- разных регистров;
- пробелов и дефисов;
- вариантов обозначения одного артикула;
- региональных суффиксов;
- альтернативных названий моделей;
- одинаковых записей из нескольких источников.

Не объединять автоматически разные региональные варианты, если их эквивалентность не подтверждена.

Не создавать повторные связи при повторном импорте.

Если одна связь подтверждается несколькими источниками, сохранять все источники без дублирования самой связи.

## 6. Защита существующих данных

Обязательно:

- сохранить существующие официально проверенные OEM-связи;
- не понижать их статус;
- не заменять официальные источники сторонними;
- не удалять пользовательские записи;
- не изменять рабочую базу автоматически;
- обеспечить безопасные миграции;
- поддерживать резервное копирование;
- выполнять импорт транзакционно.

Новые сторонние записи должны быть явно отделены от официально подтверждённых.

## 7. CLI и диагностика

Использовать существующий CLI PrinterDB.

Предусмотреть:

- dry-run;
- реальный импорт;
- JSON-отчёт;
- статистику дублей;
- список отклонённых записей;
- очередь неоднозначных записей для ручной проверки;
- повторный импорт без создания новых дублей.

Новые команды и параметры должны быть документированы в README.

## 8. Аналитика покрытия

Реализовать воспроизводимый отчёт по всей базе и отдельно по каждому производителю.

Основные показатели:

- `totalPrinters`
- `printersWithSupplies`
- `printersWithoutSupplies`
- `coveragePercent`
- `totalSupplies`
- `totalRelationships`
- `verifiedRelationships`
- `thirdPartyRelationships`
- `unknownOriginSupplies`

Также показать прирост относительно состояния до импорта.

Покрытие рассчитывать по уникальным принтерам, у которых есть хотя бы одна действительная связь с расходником.

Разделять наличие сторонней совместимости и официально проверенную совместимость.

## 9. Тестирование

Добавить тесты:

- нормализации HP, Epson и Canon;
- повторного импорта;
- сохранения нескольких источников;
- региональных вариантов;
- неоднозначных артикулов;
- корректной классификации расходников;
- защиты официальных OEM-связей;
- сохранности существующей SQLite;
- dry-run без изменения базы;
- миграций, если они необходимы.

Проверить `typecheck`, `build` и полный набор тестов.

## 10. Результаты

Предоставить:

1. Реализованные импортёры для найденных пригодных источников.
2. Подготовленные наборы данных или воспроизводимые инструкции их получения.
3. Команды dry-run и реального импорта в пользовательскую SQLite.
4. Отчёт до и после импорта.
5. Список использованных источников и ограничений.
6. Список производителей и моделей с недостаточным покрытием.
7. Обновлённый `ROADMAP.md` и README.

Не включать неподтверждённые цифры и не отмечать задачу завершённой только по результатам синтетических тестов.

## Критерии приёмки

Задание считается выполненным, когда:

- импортированы реальные связи совместимости из разрешённых источников;
- покрытие HP, Epson и Canon измерено до и после;
- новые записи не повреждают существующие данные;
- официальный статус не присваивается сторонним данным;
- повторный импорт не создаёт дублей;
- все тесты проходят;
- результат можно воспроизвести на отдельной тестовой SQLite.

Если массовый импорт не увеличивает покрытие, задача должна содержать подробный отчёт о причинах и доступных альтернативах.
