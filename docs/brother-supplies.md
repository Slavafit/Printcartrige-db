# Brother: подготовка единого каталога расходников

## Исправление моделей перед импортом (Task 025)

Полная сверка 293 сохранённых моделей с их официальными URL обнаружила три ошибки в подписях карточек:

| Было | Исправлено | Связей | Подтверждение |
|---|---|---:|---|
| `MFC-3360CN` | `MFC-3360C` | 4 | `/devices/laser/mfc/mfc3360c` |
| `MFC-295C` | `MFC-295CN` | 8 | `/devices/laser/mfc/mfc295cn` |
| `MFC-7` | `MFC-7440N` | 2 | `/devices/laser/mfc/mfc7440n` |

Каждый URL присутствует в сохранённом `data/sitemap.xml`; правильные нормализованные модели также присутствуют в сохранённом отчёте покрытия и в базе-кандидате, проверенной только для чтения. Два URL с суффиксом `-bundle` (`HL-1210W` и `DCP-1612W`) не являются ошибками: storefront-суффикс исключается только при сравнении идентичности, а название модели не меняется.

Причина — `scripts/parse-brother.cjs` принимал первое похожее на модель значение из текста карточки, но не сравнивал его с URL связанного устройства. Теперь обычная подпись обязана совпасть с URL, три подтверждённые коррекции заданы узко по точному пути и исходному значению, а любое новое расхождение останавливает парсинг вместо догадки.

Исходный HTML-кэш Brother не был сохранён в transfer-пакете или Git. Поэтому восстановление выполнено офлайн из сохранённых агрегатов `brother-compatibility.json`, `brother-verification.json`, официального sitemap и точных URL; сеть не использовалась. Это ограничение зафиксировано, а синтетический HTML служит только регрессионным тестом парсера.

После пересборки: 293 принтера, 254 расходника и 1 611 связей; нормализованных дубликатов и неподтверждённых расхождений нет. Аудит сохранил 1 606 `cross-referenced`, 4 `candidate` и 1 `not-checkable`. Dry-run против `PrinterDB-transfer-20261014-001528\printerdb-2026-10-13T12-19-26-627Z.sqlite` показал 0 новых принтеров, 253 новых расходника и 1 606 новых связей. База не изменялась.

Воспроизвести исправление и аудит:

```powershell
pnpm.cmd repair:brother-models
```

Task 024 переводит завершённый Brother-аудит в общий multi-source формат. Генератор работает только с уже сохранёнными файлами `data/brother-compatibility.json` и `data/brother-audit.json`, не обращается к сайту и не изменяет SQLite.

## Воспроизводимые команды

Сначала заново создать проверяемый пакет и отчёт:

```powershell
pnpm.cmd prepare:brother-supplies
```

Результаты находятся в `data/official/brother/brother-supplies.json` и `data/official/brother/brother-supplies-report.json`.

## Запуск из интерфейса

В разделе **Importar → Fuentes oficiales → Brother España** кнопка **Procesar HTML** запускает только офлайн-обработчик. Он читает ранее сохранённые страницы из игнорируемой Git папки `data/brother-html`, вызывает существующие модули `scripts/parse-brother.cjs` и `scripts/rebuild-brother-data.cjs`, повторно строит коллекцию, аудит и единый импортный пакет. Сетевые запросы и браузерный сбор этой кнопкой не выполняются.

UI показывает отсутствие входной папки и не позволяет начать обработку без HTML. Уже проверенный `brother-supplies.json` можно импортировать отдельно кнопкой **Importar resultado**. Перед записью сервер выполняет dry-run общего multi-source importer; запись проходит одной транзакцией и включает только связи `cross-referenced`. Статусы `candidate` и `not-checkable` сохраняются в аудите, но в SQLite не повышаются до официально подтверждённых.

Для ручного запуска используется тот же worker:

```powershell
pnpm.cmd build:server
node .\dist\src\collectors\brother.js
```

Безопасная проверка в памяти:

```powershell
pnpm.cmd db --db :memory: import:multi-source data/official/brother/brother-supplies.json --source-name "Brother España official pages" --source-category official --source-reference https://store.brother.es/ --region ES --dry-run
```

Ожидаемый результат: 1 606 валидных строк, 292 принтера, 253 расходника, 1 606 связей, ноль ошибок и ноль предупреждений. Повторный импорт проверяется автоматическим тестом и не создаёт дубликатов.

## Граница доверия

- Совместимость принимается только при статусе `cross-referenced` и точном совпадении сохранённых официальных URL принтера и расходника.
- Тип бутылки задаётся только для четырёх явно проверенных артикулов BTD180; для остальных строк сохраняется исходный тип `ink` или `toner`.
- Поле evidence хранит обе официальные страницы и дату аудита для каждой связи.
- Строгий legacy-импортёр OEM-картриджей по-прежнему принимает только ink/toner; расширенный пакет проходит через существующий multi-source pipeline.
- Рабочая/пользовательская SQLite не импортируется автоматически. Команда выше использует только базу в памяти.
